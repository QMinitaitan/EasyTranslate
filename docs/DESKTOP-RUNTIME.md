# Desktop popup lifecycle

`electron/desktop-runtime.cts` owns the concrete translation popup. The main entry supplies an Electron `BrowserWindow` factory, frontend paths, cached configuration and durable saves. This is the production owner of window creation, delivery, pinning, hiding, placement, geometry and disposal; the existing bounds and auto-hide helpers remain internal policies.

After the main document loads, one idle task creates a hidden popup. Creation and initialization never call `show()` or `focus()`. `paintWhenInitiallyHidden: false` also keeps the page initially hidden and defers its first paint until showing; initialization uses the explicit application-ready handshake, so it does not require Electron's `ready-to-show` event. This avoids the extra hidden-paint GPU allocation observed in the native comparison. Shortcut handling first calls `beginSelectionCapture()` to discard superseded queued work, then captures the original foreground selection, and finally calls `showTranslation(text)`. A newly initialized popup cannot activate an older queued trigger while the next capture is running.

The popup becomes application-ready only when its Vue configuration and trigger listeners are initialized and it invokes `popup:ready`. Main accepts this declaration only from the current popup's exact `webContents`. `did-finish-load` and `ready-to-show` do not grant application readiness. Before readiness, one pending trigger retains the latest captured text. An authenticated `popup:unready`, a new main document or renderer loss resets readiness; same-document navigation and subframe loading preserve it. This distinction matters because Electron can emit spinner-start and same-document navigation together when a hidden popup is reused.

Repeated triggers reuse one window. Destroying it disposes its owned timers and listeners; a replacement must initialize and declare readiness again. Pinning preserves topmost visibility, ordinary blur retains the existing grace period, and native movement cancels drag-start hiding. Dimensions and placement retain the existing bounds migration and minimum-size rules. On Wayland, placement stays with the compositor and unsupported global coordinates are neither read nor persisted.

`flush()` captures final live bounds, drains the geometry debounce and awaits the latest geometry save. Quit must await it before draining configuration writes. Reset clears both the saved position and any obsolete pending geometry. Save errors remain observable through the supplied callback and `flush()` rejection.

The public module seam is exercised in `tests/desktop-runtime.test.cjs`, with the actual policies and a simulated Electron window boundary. Native Windows focus/selection/clipboard and latest-queued-trigger checks are reproducible with `scripts/testing/run-prewarm-native.ps1 -Mode focus` and `-Mode queue`, after `npm run build`. They use isolated profiles, synthetic credentials and controlled transport. Performance evidence and its limitations are recorded separately in the dated performance report.
