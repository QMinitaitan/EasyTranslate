# Translation sessions: single-engine migration

`electron/translation-session.cts` owns current-session identity and automatic history eligibility. Its public `start({ text, target, engine, requestId })` returns a generated `sessionId` and a `done` promise. `subscribe` observes current loading/success/error/empty snapshots; `current` returns a copy; `cancel` and `dispose` end ownership and attempt cancellation. Replacement settles the old caller immediately as `superseded`, even if an injected transport ignores its AbortSignal and never settles promptly. A late success or failure cannot publish a snapshot or acquire automatic history eligibility.

The service injects execution, history persistence and time at the seams agreed in specification #1. Successful text is visible to subscribers before persistence finishes. The completion result distinguishes translation success from `historyError` and never manufactures an identifier on a rejected or missing save. A queued storage adapter receives `isCurrent()` so it can recheck eligibility before admitting an automatic write. The legacy history implementation remains synchronous in this migration stage; #7 supplies durable asynchronous storage and uniform history notifications.

`translate:do` validates the wire request, reads configuration once, selects the engine and delegates to this service. The same route receives shortcut-triggered translation, edited source and retry. IPC replies carry both session identity and caller request identity. Popup presentation also owns a local sequence: an older invoke completion or an older asynchronous engine refresh cannot change a newer view. Empty selection, switching to the legacy race, a new accepted shortcut and renderer teardown cancel pending singles. The actual network adapter receives the service's AbortSignal; cancellation support is introduced by #5 without using cancellation as the correctness boundary.

Race execution remains on its existing entry in #3. It can supersede a pending single, and existing race result subscriptions/sorting remain usable. #4 moves race work into the same service and removes its independent lifecycle; #3 does not claim that legacy race history is already protected from every cross-mode replacement.

Behavioral tests cover ignored cancellation, old success/failure after B, immediate supersession settlement, empty output/configuration, existing history retention, one save per single session, persistence rejection, admission of queued writes and subscription/disposal behavior. The reentrant presentation case was observed red (`A,B` history instead of `B`) before adding the current-session recheck immediately before saving.

Controlled Electron renderer smoke (2026-10-20) used production-built Vue/preload, real IPC, an in-process synthetic HTTPS response, isolated configuration/history/userData and a warmed popup. A delayed A was replaced by B through the source editor's Enter action: B remained visible after A returned and history contained only B. A current failure displayed its error and the actual retry button produced the expected result/history. Two BrowserWindows remained. The initial run used the legacy adapter; a repeated run after merging the tested #5 transport checkpoint `14ee48a` also recorded one real adapter-to-request `destroy()` cancellation attempt. The synthetic request deliberately ignored destruction, so ownership correctness did not rely on cancellation stopping its late callback. A behavioral test additionally runs the session and real provider service together against a controlled transport and observes request destruction, B's result and B-only history.

The smoke also delayed an old trigger's configuration refresh, then edited a newer source before that refresh returned. It initially failed with `TRANSLATED QUEUED_OLD` replacing `TRANSLATED NEWER`. Invalidating queued trigger refreshes on every newer translation intent fixed it: only `NEWER` was translated and saved.

This verifies renderer/IPC behavior; the shortcut action and selection were injected, transport was synthetic, and no native shortcut/clipboard performance or paid API behavior is claimed by this smoke. Original real Windows shortcut/clipboard evidence remains in `docs/performance/`; full installed-product verification is #11. The deterministic smoke result is `docs/validation/2026-10-20-single-session.json`. Reproduce on Windows with PowerShell 7.4+ after `npm run build` and provisioning the Electron binary:

```powershell
pwsh -File scripts/testing/run-session-ui-smoke.ps1
```

The runner uses a fresh `.runtime/session-ui-*` fixture directory and restores no personal data because it never reads or writes personal config/history or the system clipboard. It emits logs, a result JSON and a screenshot of only the synthetic popup. Optional `-Repo`, `-ElectronPath` and `-OutputRoot` arguments support alternate checkouts/binaries; an existing nonempty output directory is rejected. Every managed app self-exits with a 20-second maximum deadline. No external provider request is possible through this controlled transport.
