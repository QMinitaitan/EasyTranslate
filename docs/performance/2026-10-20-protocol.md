# Frozen Windows measurement protocol (2026-10-20)

Written before optimizing source. Baseline application source: 6c85be6 (same application as 75516d6); production Vite assets in the original checkout. Electron dependency installed through its package install script; no installed EasyTranslate replacement.

Machine: Windows build 10.0.26200, AMD Ryzen 7 6800H, 8 cores / 16 logical processors, 16,312,639,488 bytes physical RAM. Shared interactive desktop; unrelated applications remain open. Results describe this machine under those conditions, not universal guarantees.

Use an external launcher to require the real main module unchanged. Instrument exported getSelection, native child_process.execFile, BrowserWindow lifecycle, IPC and DOM MutationObserver. HOME, USERPROFILE and Electron userData are isolated per run. All provider configurations are disabled except a fake-key OpenAI-compatible provider. The https.request transport is replaced inside this process with a deterministic 50 ms successful response; no real network, credentials or paid calls. The real adapter, IPC, Vue, file history, actual global shortcut, real Windows PowerShell Ctrl+C helper and system clipboard are exercised.

Foreground source: a standalone PowerShell WinForms TextBox containing synthetic English text; select text and invoke Alt+Q using user32 keybd_event. A clipboard sentinel fixture is installed and restoration is checked in the Electron selection wrapper; the outer runner restores prior clipboard contents supported by WinForms after the complete run. No user's configuration/history is read.

Samples: 7 independent process launches with fresh isolated profiles, each first invoke after main renderer load; first launch additionally has 30 warm invokes at a steady cadence, one empty selection, 30 seconds idle before first invoke and after repeated invokes. Relaunch uses OS file cache as found; 'cold' means new process/profile, not reboot/flushed disk cache. Record all observations, including missing result/empty/failure, and don't discard slow trials. The first result timing uses main IPC completion and DOM observer; observer entry is a proxy for rendered DOM availability, not photometric screen presentation.

Record process launch to app ready / main did-finish-load, shortcut callback to selection, helper execution, popup show, document load, first backend result, first visible DOM result. App-ready-to-handler time is observed, not an app-level readiness handshake. Baseline has no such handshake. Full descendant process CPU seconds, private bytes and working set are sampled by an external .NET worker, including native helper children. Per-process working sets are summed (shared pages may be counted more than once); report private bytes alongside them. CPU is aggregate process CPU delta / wall time / 16 logical processors. Approximately 100 ms resource samples throughout (transient and idle); launcher window/process health telemetry every 500 ms. Sampling/instrumentation overhead exists identically in both versions.

Freeze comparison thresholds before optimization: first-popup local path (shortcut to popup show and to DOM result) P50 must improve, with no added first-trigger loss; selection capture semantics/empty guard/clipboard restoration must hold. Warm path P50/P95 must not worsen by more than max(15%, 50 ms) relative to baseline; idle normalized CPU must stay <= max(baseline+0.5 percentage points, 1%). Preheat may add one renderer, but steady private memory must stay <= baseline-after-first-popup + max(15%, 30 MiB); no linear retained process/window growth across 30 translations. Compare both P50 and P95 and observed range; 7 first samples gives a coarse P95 (maximum) and will be labeled accordingly. Exceedance requires explanation/fix, not retroactively relaxed thresholds. Real external network speed is excluded; transport remains exactly 50 ms.

Incomplete/unavailable native or packaged checks must be marked explicitly. This harness is for original-source and later same-condition comparison; it does not by itself prove NSIS installation, Linux runtime or third-party service correctness.
